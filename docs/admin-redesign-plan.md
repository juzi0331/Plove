> 状态：**第一批已实现**（2026-09-30）｜第二批 / 第三批待排期。
> 第一批的落地说明与**组件清单**在 [docs/steps/09-admin-redesign.md](steps/09-admin-redesign.md)。
> 前情：阶段 7 让后台「能用」（4 个页面、9 个接口、201 个测试）。
> 这份提案回答下一步：**① UI 为什么显得工业、往哪改；② 还能加哪些功能、怎么分批。**

## 一、体检：为什么现在"工业"、"功能少"

| 现状 | 问题 |
| --- | --- |
| 2 个菜单项（总览 / 激活码） | 信息架构只有一层，所有东西挤进两个页面 |
| 4 个页面全是「灰底 + Element 默认表格 + 按钮」 | **没有设计层**：颜色、间距、圆角、阴影全是库默认值（#409EFF / #F5F7FA / 4px） |
| 功能只覆盖「码 + 设备」这一竖切 | 后台里**看不到爬虫侧（源）、系统侧（凭证 / 日志 / 配置）、任何趋势** |
| 表格是唯一的呈现方式 | 状态没有颜色语义、没有对比、没有图，只能一行行读 |
| 反馈只有一闪而过的 `ElMessage` | 操作完想回看"刚才干了什么"，没有地方 |
| 没有空状态 / 骨架屏 / 暗色 / 快捷键 / 响应式 | 这些不是装饰 —— 它们决定"新运维上手要问几次别人" |

**换一个问法看差距** —— 后台的本质是回答五类问题，现在只答得上一类半：

| 运维的问题 | 现在能答吗 |
| --- | --- |
| 现在有没有人在用、用了多少？ | 半（只有码列表里的 `device_count`） |
| **为什么这个源没内容了？** | 半（总览给了熔断/预热，但看不到最近的错误、看不到各源对比、不能自检） |
| 刚才我干了什么？ | ❌（审计只写进日志文件，界面上没有） |
| 源站是不是改版了 / 变慢了？ | ❌（没有耗时对比、没有故障历史） |
| 用户端现在长什么样？ | ❌（要看就得开 App） |

> 一句话诊断：**现在的后台是「数据库的只读面板 + 三个动作」，不是运维的驾驶舱。**

## 二、UI 重设计方向（不换技术栈）

不换组件库：Element Plus 按需引入已经进后台自己的 chunk（用户端首屏没被压重），
重设计的做法是加**设计层**，而不是换框架。三层：

### 1. 设计 token（新增 `frontend/src/admin/theme.css`）

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 底色 | `#f6f7f9` / 卡片 `#fff` / 边框 `#ebedf0` | 比 Element 默认的灰更冷、更轻，表格不再"铁板一块" |
| 文字 | 主 `#1f2329` / 次 `#5f6672` / 弱 `#8a9099` | 建立三级信息层级，标题和说明分得开 |
| 强调色 | 深墨色（主操作、侧栏激活） | 按钮不再是刺眼的 #409EFF |
| 品牌色 | `#ee0a24`（与用户端一致）**克制使用** | 只给品牌标识 / 危险动作；避免"满屏红按钮" |
| 圆角 / 阴影 / 间距 | 10px / 两级 / 4 的倍数 | 视觉节奏统一 |

做法：用 CSS 变量覆盖 Element Plus 主题（`--el-color-primary` 等），
**不改组件用法** —— 这样按需引入的收益保留，将来换主题也只动一个文件。

### 2. 布局

```
┌──────────────────────────────────────────────────────┐
│ 面包屑 ················  自动刷新 | 只读模式 | 主题 | 退出 │  ← 顶栏（56px）
├────────┬─────────────────────────────────────────────┤
│ 概览    │  页面头：标题 + 一句说明 + 操作区              │
│ 运营    │  ┌────┐ ┌────┐ ┌────┐ ┌────┐               │
│  激活码 │  │统计│ │统计│ │统计│ │统计│  ← 统计卡      │
│  设备   │  └────┘ └────┘ └────┘ └────┘               │
│ 内容源  │  主体（表格 / 卡片 / 详情）                  │
│ 系统    │                                             │
└────────┴─────────────────────────────────────────────┘
```

* 侧边栏**分组**（概览 / 运营 / 内容源 / 系统）+ 图标，可折叠，记住折叠状态；
* 页面模板统一：**页头（标题 + 一句说明 + 操作区）→ 统计卡 → 主体**；
* 表格页顶部操作区**粘性**（滚动时搜索/刷新/发码不跑掉）。

### 3. 状态三件套（每个页面都要有）

| 组件 | 说什么 | 现在 |
| --- | --- | --- |
| 骨架屏 | "在加载，不是没数据" | ❌ 白屏一闪 |
| 空状态 | "为什么空 + 下一步按钮"（如"还没有码 → 去发码"） | ❌ 空表格 |
| 错误态 | "错在哪 + 重试按钮"（保留 request_id 方便对日志） | 半（只有一行红字） |

### 4. 暗色模式 + 响应式

* 暗色：Element Plus 自带 dark 变量（`element-plus/theme-chalk/dark/css-vars.css`），
  跟随系统 + 手动切换；偏好存 `localStorage`（**只是界面偏好，不是凭证**请不要混）。
* 响应式：`≥1280` 正常两栏；`<1024` 侧栏自动折叠；手机上**至少能查码、看设备、踢人**。

### 5. 表格体验统一

列宽记忆 · 粘性表头 · 行悬停才出现的操作 · 双击进详情 · 时间一律相对（悬停看绝对）·
危险动作按钮永远在最右侧且配色统一。

## 四、建议的落地批次

按「改动面」分三批，每批都是一个能单独验收的里程碑。

### ✅ 第一批 · 只动前端（零契约风险，最能看出"新后台"的样子）

G1–G7、G11 · A1–A2 · B7–B9 · C2 · F4。**（已实现）**

验收：打开 `/admin`，不是灰色的表格堆，而是**有告警、有卡片、有骨架、有暗色**的工作台；
`npm run build` 绿，后端一行未动。 —— 已完成，详见 [步骤 9](steps/09-admin-redesign.md)。

### 第二批 · 小契约（加接口/参数，不改现有语义，前端不会返工）

B1–B4 · F3（审计落库，B5 依赖它）· F1（令牌热改）· C1/C3 · D3/D4/D8 · A3–A6。

验收：每个新接口都有契约 + 离线测试；`pytest` 全绿且数字同步。

### 第三批 · 新表 / 跨端（必须先拍板再动）

D1/D2（远程配置：源开关、排序）· E1（公告）· B5/B6（码详情时间线、二维码）·
A7–A9（趋势、缓存明细）· C4/C5 · E2（kill switch）。

> 排序理由：第一、二批都是"加法"，不会改变现有 19 个接口的形状；
> 远程配置也一样（新增 `config` 接口），但它决定用户端"看到什么"，
> 所以放到最后，等后台自己的形状稳定了再动。

## 五、明确不做（这版）

| 不做 | 为什么 |
| --- | --- |
| 上传爬虫 | 远程代码执行入口；形态（谁写 / 怎么审 / 坏了怎么回滚）没定之前不做 |
| 多用户 / 角色权限 | 只有一个运维；等有第二个人再上 F2 |
| 图表库（ECharts 等） | 数据量不值得；先用 CSS 迷你条 / 环形图，真要趋势图再说 |
| 用户行为埋点与播放统计 | 用户 < 30 人，投入产出不成比例 |
| 分片级去广告 | 属于播放代理（阶段 9），后台里最多放一个开关 |

## 六、需要你拍板的五件事

| # | 事项 | 选项 | 建议 |
| --- | --- | --- | --- |
| 1 | 视觉方向 | A 深色侧栏 + 浅色内容（现代面板风）· B 全浅色极简 | A（与用户端的红只做点缀，不冲突） |
| 2 | 新增依赖 | `@element-plus/icons-vue`（图标）· `qrcode`（二维码） | 都加：小、官方、无副作用；图表库不加 |
| 3 | 源开关（对应阶段 6b-3） | 这次做 / 往后放 | 这次只做后台侧，用户端先不动 |
| 4 | 审计日志落库 | 做 / 先维持日志文件 | 做（F3）：码详情时间线、事后对账都指望它 |
| 5 | 后台令牌热改 | 做 / 先维持环境变量 | 做（F1）：改令牌要重启进程这条，第二个人一来就碍事 |

拍完板后，实现流程照 [how-to-add-a-feature.md](how-to-add-a-feature.md)：
写模型 → 登记契约 → 导出 → service → 路由 → 测试 → 文档 + 同步 PROGRESS 数字。

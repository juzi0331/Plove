# 步骤文档

每完成一个步骤，就在这里留一份**详细文档**：这一步做了什么、为什么这么做、怎么验证、
以及**没做什么**。编号递增，一份文档对应一个步骤。

## 为什么要有这个目录

因为"做完了"和"看懂了"是两件事。代码能告诉你**怎么实现**，但告诉不了你
**它为什么存在、能解决什么问题、边界在哪**。尤其是跨步骤的决策——
比如"为什么非要有一层 API"，散在一堆会议记录里就等于没有。

所以规矩是：**每步一个文档，写给人看，不写给编译器看。**

## 文档该包含什么

| 段落 | 内容 |
| --- | --- |
| 这一步干了什么 | 一句话说清交付物 |
| 它是什么 / 为什么 | 解释设计意图，**尤其是容易被误解的地方** |
| 现在能干什么 | 诚实的清单（接口、命令、能力） |
| 怎么验证 | 可复制粘贴的验证步骤 |
| 没做什么 | 明确边界，避免误以为已经做完了 |
| 下一步 | 衔接 |

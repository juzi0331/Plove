## 一、设计语言：为什么是纯黑 + 红 + 几乎没有圆角

三条都不是审美偏好，各有理由：

| 选择 | 理由 |
| --- | --- |
| **纯黑 `#000`**（不是 `#111`） | ① 海报是主角，浅底会把海报衬得发灰；② OLED 手机上真的省电，而用户一集要看 40 分钟；③ 播放页本来就是全屏黑，首页跟着黑就不会在跳转时"闪一下白底" |
| **红 `#e50914`** | 这个颜色**只在"要看/要播"的地方出现**（主按钮、当前源标记、字数标）。全站只有一个强调色，用户扫一眼就知道该点哪 |
| **圆角 4px** | 大圆角会立刻变成"卡片 App"，而这个方向要的是"影院"。例外只有两处：海报卡（`shadow` 唯一破例的地方，让它像"立起来"）和评分金色 |
| **字重拉开对比** | 标题 800、正文 400，中间那档基本不用。影院风靠字重和留白撑，不靠边框和背景块 |

**所有颜色只在一个地方定义**（`styles/app.css` 的 `--plove-*`），组件里不再写十六进制。
Vant 那套也一样：整套覆盖 `--van-*` 变量，**不去重写 `.van-xxx` 选择器** —— 后者在升级 Vant 时最容易炸。

## 二、最关键的一件事：**没有海报也必须好看**

这是整套设计真正的地基，因为它来自一个实测结论：

> **`ncat21` 的海报一张都拿不到。** 而首页原来默认走的就是它。

所以"缺图"不是异常，是**常态**。原来的实现缺图时显示一个灰底加"无图"两个字 ——
78 张海报全是那个样子，整个界面看起来就是坏的。

### 做法：渐变底永远在，图加载成功盖上去

`PosterImage.vue` 的结构是两层：

```
[ 渐变底 + 片名大字 ]   ← 永远渲染，缺图时它就是成品
[ <img> 加载成功盖上去 ]  ← 有图时把上面那层遮住
```

好处有三个，都是实打实的：

* **没有白闪** —— 图片解码那几百毫秒里，位置上是同一块深色底，而不是空白格子突然"啪"地出现一张海报；
* **缺图是一张标题卡**，不是一块故障；
* **不用判断"图挂了没"**，两层天然叠加，逻辑简单。

### 颜色是**算出来的**，不是随机的

`utils/art.ts` 用片名算一个稳定的色相（`titleHue`），再配一个 +32 度的副色出渐变。

**为什么必须稳定**：随机 цвета 会让界面每次刷新都在闪颜色，看起来像故障；
而同一部片永远是同一个颜色，用户第二次看到会认得出来 —— 这时候"缺图"就变成了**一种设计**。

同一份算法还用在**首页头图的背景**上（`url(...)` 和 `linear-gradient(...)` 同时给
`background-image`，图挂了底下那层渐变就露出来）。所以头图的氛围色和头图里那张标题卡
是同一个颜色，看起来是一套东西，而不是两个随机色块。

> 顺带一个 CSS 细节：片名字号用 `clamp(12px, 8cqw, 20px)` + `container-type: inline-size`，
> 于是**同一份字号规则**在 107px 的列表格子和 164px 的头图里都合适 ——
> 不这么写就得按位置传字号参数，迟早会不一致。

## 三、首页为什么变成"头图 + 横向行"

原来首页是：导航条 + 分类 chips + **三列九宫格** + 若干九宫格。

改成：**头图（billboard）+ 分类 chips + 若干横向滚动行**。

理由不是"Netflix 这样"，而是**视线路径**：九宫格里每张海报的分量完全一样，
用户得自己一个个挑；头图先替他做一次决定（今晚看这个），剩下的用横向行铺开。
横向行还有个副作用是**更好的信息密度** —— 一屏能露出的片名比九宫格多。

具体实现上有三处值得记：

1. **顶栏是 `sticky` + 负下边距**，所以它在顶部时**透明叠在头图上**，滚动过 12px 后才变实心黑。
   一直实心会在头图上切出一条黑带；一直透明则滚动后白字压在亮海报上读不清。
2. **头图背景是同一张海报放大 + 模糊**（`filter: blur(26px)` + `scale(1.25)`）。
   海报是 2:3 竖版，直接铺满一块横版区域要裁掉一半；模糊之后它变成一层"氛围色"，
   既填满画面又不会因为裁切显得奇怪。
3. **换源入口在右上角**，每屏都可见。它不是装饰：源站随时会坏，这是用户当时唯一能自救的手段。

## 四、两个实测发现（都不是设计问题，但决定这个界面能不能用）

这两个是这一步**挖出来的真问题**，比视觉本身重要。都是"查海报为什么是灰的"顺手查出来的。

### 1. `ncat21` 的海报在任何地方都拿不到

| 测试方式 | 结果 |
| --- | --- |
| curl，不带 cookie | `403`（openresty） |
| curl，带**有效的** `cdndefend` 闸门 cookie | `403` |
| curl，带全套 Chrome 头（含 `Sec-Fetch-*`、ch-ua） | `403` |
| **真浏览器** `<img>`（同一张图） | 连接层失败，`responseStatus: 0`，约 1s |
| 第三方服务端代理 `images.weserv.nl`（欧洲 IP） | `404`（上游取不到） |
| 第三方服务端代理 `api.allorigins.win`（美国 IP） | `520` |

**先排除了"是不是爬虫没带 cookie"**：同一份 cookie 对**页面**有效（首页 `200`、227KB HTML），
对图片路径就是 `403`。

**再排除了"是不是只拦我们这台机器"**：两个不同出口的第三方服务端代理也失败。

**还扫了整页的图片地址**：首页 187 张 `<img>` 全在 CDN `vf.esadj.com` 上，
但那个 CDN 只放**站点静态 UI 资源**（logo、CSS、`logo_placeholder_vertical.png` 占位图），
海报是懒加载的**相对路径** `/vod1/vod/...`（解析到 `www.ncat21.com`，也就是被拦的那个）。

> **结论：图片代理救不了它。** 我原本推荐"加后端图片代理"的理由是"两个源的海报都能出"，
> 这个前提被证伪了 —— 403 来自源站自己的 WAF，代理换了出口也没用（第三方代理实测同样失败）。
> 代理仍然有价值（缓存、防盗链、私有化出口、未来源），但它**不是这个问题的解**。

### 2. `ai2048` 的 m3u8 有**来源白名单**，浏览器里必然播不了

| m3u8 请求 | 结果 |
| --- | --- |
| 不带 `Origin` | `200` + `access-control-allow-origin: *` |
| 带 `Origin: http://127.0.0.1:5173`（浏览器实际行为） | **`403 Forbidden`** |
| 带 `Origin: https://2048ai.vip`（源站自己） | `200`，且 ACAO 只回显它自己 |
| 海报（同一主机） | `200`（图片不受影响） |

浏览器里看到的是 `hls.js` 报 `manifestLoadError`，`net::ERR_FAILED` —— 根因就是这个 403。
**服务端取完全正常**（实测 `200`、13KB、`application/vnd.apple.mpegurl`），流还是 **AES-128 加密**的
（key 在另一个域名上）。

两个推论：

* **这正好是阶段 9「播放代理」存在的理由**：m3u8 必须**服务端取、改写后再从我们自己的域发出去**。
  顺带还要处理那个加密 key 的地址。
* **iOS / WKWebView 反而可能不受影响**：原生 `<video src>` 播放跨域 m3u8 **不发 `Origin` 头**，
  所以那条路是通的 —— 而封成 ipa 之后走的正是这条路。也就是说
  **同一个源，桌面上播不了、iPhone 上能播**。这一点等 6b-2 真上线之后要在真机上确认。

## 五、顺手修掉的一个真问题：选集按钮全是剧名

`ai2048` 会把**整部剧名**塞进每一集的 `ep_name`，于是选集按钮变成七个一模一样的
"我是爸爸的新妻…"，完全没法用（原来的四列网格也一样）。

改法是一条**有判据的**规则，不是特判某个源：

```
ep_name 只在「够短（≤8 字）且不等于/不包含剧名」时才当标签用
（那时它是真的集名或画质标识，如 HD、第3集）
否则一律回退到**集号**
```

剧集本来就是按集数找的，回退到数字反而更好用。
同一个判据也用在播放页的 URL 参数上 —— 否则播放页会显示
"第 1 集 · 我是爸爸的新妻子第一集" 这种废话。

## 六、现在能干什么

| 页面 | 现在长什么样 |
| --- | --- |
| 激活 | 黑底 + 红色 **PLOVE** 字标 + 两个深色输入框 + 红色主按钮（"登录页"的熟悉形状） |
| 首页 | 头图（模糊氛围色 + 海报 + 片名 + 红色「开始观看」）+ 分类 chips + 横向行 |
| 分类 | 三列深色海报网格 + 骨架屏 + 无限下拉 |
| 详情 | 头图 + 海报 + 片名 + 评分（金色）+ 红色「开始观看」+ 折叠简介 + 线路 tabs + 选集网格 |
| 播放 | 无导航条、全屏黑、返回键浮在画面上；说明收进折叠 |
| 选源 | 深色卡片列表，当前源红框 + 「当前」标记 |

顺手记两个"顺手做了"的改善：

* **加载态从转圈换成骨架屏**（`StateBlock`）。转圈只说明"在忙"，骨架屏还提前说明了
  "会出来什么"；页面结构提前就位，数据到了不会整页跳一下。
* **Vant 用量从 10 个降到 5 个**（只剩 NavBar / Button / Tabs / List / Dialog，加 Toast）。
  表单、列表卡片、空态、图片都换成了自己写的 —— 这让"Vant 按需引入"从"要配一堆东西"
  变成"值得做"（现在还有 **78 KB(gz)** 的整包 Vant 在主包里）。

## 七、怎么验证

```bash
cd frontend
npm run build          # vue-tsc + 打包；类型错误会让构建失败
npm run dev            # → http://127.0.0.1:5173
```

浏览器 F12 → 设备工具栏 → 手机尺寸（iPhone 14 之类）。然后**两个源都走一遍**：

* `ai2048` → 海报齐全，是"影院"那一版；
* `ncat21`（首页右上角「换源」）→ **海报一张都不出，但界面仍然是设计过的**：
  每部片一个固定配色 + 片名，头图背景也是同一配色。**这一版才是这套设计真正的考点。**

还要特别看一眼的：分类页海报比例（应恰为 **2:3**，实测 107×161）、
选集按钮显示的是**集号**而不是一长串剧名、播放页的错误文案不是"网络错误"。

## 八、这一步**没有**做

| 没做 | 说明 |
| --- | --- |
| 改路由 / 加页面 | 说好"先视觉层"。没有底部 Tab、没有搜索页、没有"我的" |

| Vant 按需引入 | 用量已经降到 5 个，值得做，但属于构建配置改动，单独一步更稳 |
| 后台面板 | 明确交给另一个对话，`src/admin/` 一行没动 |

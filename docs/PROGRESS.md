### ⚠️ 当前两个卡点（都是重设计时挖出来的实测结论）

| 卡点 | 实测 | 意味着 |
| --- | --- | --- |
| **`ncat21` 的海报一张都拿不到** | 同一份闸门 cookie：**页面 200**（227KB HTML）、**图片路径 403**。真浏览器也是连接层失败；两个不同出口的第三方服务端代理同样是 404 / 520 | 源站 WAF 拦的是图片路径，**换出口的信号也救不了** 。界面因此必须“缺图也好看”，已按这个前提重做 |
| **`ai2048` 的 m3u8 有来源白名单** | 不带 `Origin` → 200；带 `Origin: http://127.0.0.1:5173` → **403** | 浏览器里必然 `manifestLoadError`，**阶段 9 播放代理从“按需”变成“现在就需要”**。但原生播放（iOS/WKWebView）不发 `Origin`，所以那条路可能是通的 |

## 二、踩到并修掉的坑（都写进文档了）

| 坑 | 教训 |
| --- | --- |
| NAS 上 MySQL 的端口是 **33306** 不是 3306 | 容器里 `ss` 看着 `*:3306` 正常，外面却是"主动拒绝"—— 那是端口映射没出来，不是防火墙 |
| 宝塔建库默认只授权 `localhost` | 端口通了之后会换成 `Access denied`，两件事要一起改 |
| 假爬虫文件 `__init__.py` 会被当成一个源 | 它的首字符是下划线，**恰好通过了** key 的正则 |
| **熔断永远不会生效** | `meta` 每请求必经且成功即清零失败计数 → "meta 能通、抓内容超时"的源永远熔断不掉。已修 |
| **超时配小了** | 按"ncat21 约 4s"配的 10 秒，后来真的超时了一次（它现在会到 8.9s）。已改成 20/25 秒 |
| HTTP 头不能放非 ASCII | 拿中文当测试令牌，httpx 在发请求前就编码失败了。**这个坑踩了两次** |
| 两个 `APIKeyHeader` **撞名** | 不给 `scheme_name` 就用类名，后声明的直接覆盖前一个 —— Swagger 里点内容接口会发后台令牌，全部 401。已修 + 加了契约级回归测试 |
| 协议相对 URL `//evil.com/x` | 只检查"以 / 开头"的实现会**正好把它放过去**，主机就被换掉了 |
| 控制台里 `✓` 会炸 | Windows 控制台是 GBK，脚本里别输出非 ASCII 之外的符号 |
| **视频拿到了地址却是空的** | 给 `playback` 赋值后马上挂播放器，而 `<video>` 还在 `v-if` 后面——**Vue 渲染是异步的**，那一刻元素还不存在。现在 `await nextTick()`，而且拿不到元素时会 `console.warn`（这类失败**不报错**，只看请求日志会得出"一切正常"） |
| "防盗链"提示误报 | 一开始写成"带 headers 就提示"，而 `ncat21` 明明能播也弹了 —— 现在只在真的播不出来时才显示。**一个总出现的警告等于没有警告** |
| 生成器报了 6 处"契约冲突" | 其实是同一类型在多份契约里各有定义（独立那份带 `description`）。改成**比较生成的 TS 文本**而不是比 JSON |
| **`ncat21` 的海报一张都拿不到** | 同一份闸门 cookie：页面 200、图片 403。真浏览器、第三方服务端代理全失败 → **图片代理救不了它**（换了出口的信号也失败），界面只能按"缺图也好看"做 |
| **`ai2048` 的 m3u8 有来源白名单** | 不带 `Origin` 是 200、带我们的 `Origin` 就是 403 —— 浏览器直连必然 `manifestLoadError`。而原生 `<video>`（iOS/WKWebView）不发 `Origin`，**所以同一个源桌面上播不了、iPhone 上可能能播** |
| 有的源把**剧名**塞进 `ep_name` | 选集按钮变成七个一模一样的"我是爸爸的新妻…"。改成"够短、且不含剧名才当标签，否则回退到集号" |
| 后台的写接口：`get_db` 的 commit 在**响应之后** | 点完"停用"那一行偶尔还是旧值。写接口现在都显式 `commit_now(db)` —— **客户端读到 200 时，变更已经落库** |
| **抢回活跃位之后的第一个请求仍然 409** | 和上一条同一个根因，但这里是**必然**会碰上的时序（客户端拿到 200 一定立刻重拉数据），撞上概率约一半。**用 curl 手工测永远测不出来**：两次请求之间隔了十几毫秒。修法是让 `redeem` 也显式提交 |
| "窗口很小可以忽略" ≠ "时序上必然" | 上一条的教训：只要概率不是 0，在真实使用频率下就一定会发生 |
| `App.vue` 是用户端/后台**共用**的根组件 | 用户端的"已在别的设备上使用"弹窗漏进了后台（还带着会去**抢活跃位**的按钮）。全局的横切逻辑要先问一句"它对不对后台生效" |
| 看板的源健康表按"碰过的源"列 | 打开是空表 —— 看起来像"没有源"而不是"还没探测"，**比没有更糟**。改成按目录扫描 + 给 `SiteHealth` 加 `probed` |
| 被踢后抢回，过期的错误还挂在屏幕上 | 用户得自己去找"重试"按钮。加了 `device.restoredAt` 信号，四个视图 `watch` 后自动重载 |
| **测试隐式依赖开发机的 `.env`** | `.env` 里一配上 `PLOVE_ADMIN_TOKEN`（装了后台面板就一定会配），三个"空令牌 = 后台 403"的用例就变红 —— 而它们守的是最要紧的安全默认值。夹具现在**显式钉成空**。**测试不能依赖开发机上的 `.env`** |

## 三、已拍板的关键决策（避免以后重复讨论）

| 议题 | 决定 |
| --- | --- |
| 后端形态 | **方案 B：服务端爬虫**，前端只调统一 API（浏览器直连源站会撞 CORS / 反爬闸门 / 代码泄露三堵墙） |
| 后端技术栈 | **Python + FastAPI + Pydantic + SQLAlchemy**（与爬虫同语言，一套校验模型三端共用） |
| 前端与打包 | PC Web（Vue3 + Vite + Vant + hls.js）→ Capacitor 封 ipa；**ipa 只打一次**，之后靠 WebView 直载远程热更新 |
| 激活码 | **时长制、不做注册**；一码多设备但**同时只能一台在线**（互踢）；时长从**首次激活**起算 |
| 单会话实现 | 活跃位只在有人**主动抢**时变 —— 所以**不需要**"心跳超时释放"，切后台/锁屏都不会误踢 |
| 爬虫语言 | Python（`httpx` + `parsel`），**硬隔离用子进程**（威胁模型是稳定性，不是安全沙箱） |
| 数据库 | MySQL（宝塔 / NAS）。**表结构只用可移植类型**，本地测试跑临时 SQLite |
| 数据存什么 | **首页/详情/剧集都不入库** —— 它们进内存缓存；MySQL 只存激活码、设备（日后加远程配置） |
| 缓存 | 进程内 TTL+LRU + 防击穿（**不上 Redis**），用户 < 30 人时命中率完全一样 |
| 数据新鲜度 | 请求时按需抓 + **定时预热入口页**（周期 24h，TTL 25h） |
| 稳定性 | 硬超时 20s/25s · 每站并发 2 · 全站并发 4 · 连续失败 5 次熔断 60s · 半开放 1 个探针 |
| 数据分层 | 站级动态分类（爬虫返回）+ 影片级统一四字段 `vod_id/vod_name/vod_pic/vod_remarks` |
| 带宽现实 | 服务器 10Mbps → VIP 定位是"**绕限制兜底 + 只中转 m3u8 索引**"，分片让客户端直连源站 |
| 爬虫生成器 | **本地小网页**，声明式配置 + 逃生舱，**最后阶段**做（现在样本太少，抽象一定会错） |
| 部署 | **单机**：一个 VPS 跑一个 FastAPI 进程（顺带托管前端静态文件）+ 一个 MySQL（走 `127.0.0.1`，对外不可见） |
| 契约来源 | Pydantic 模型是唯一事实源，`contracts/schemas/*.json` 是**生成物**，过期测试会红 |
| 后台面板 | 挂**同一域名的 `/admin`**（不另开端口/子域）；凭证是 `X-Admin-Token`（环境变量，**留空 = 全部 403**）；令牌存 **sessionStorage**（关标签页即失效）；设备列表**永远不给令牌明文**（只有前 6 位）|

| 11 | ipa | 打包一次，之后部署即热更 | ⬜ 最后一步 |

**为什么远程配置 + 部署排在前面：** 前端一写完就会被绑死在当前接口上，
而源开关和远程配置会改变"接口返回什么"。先后端完整、再动前端，前端才不会返工。
部署更早做还有一层好处：**越早上线，越早暴露"源站被封/超时/改版"这类真问题**。

> **实际执行时的修正（写在这里免得以后对不上）：** 先做了前端骨架（阶段 7a），
> 因为"得先看见整体才能判断哪里不对"。这个顺序没有打破上面那条理由，
> 但成立的理由是具体的：**远程配置是"加法"** —— 它只新增一个 `config` 接口和几个字段，
> 不会改变现有 19 个接口的形状，所以前端不会因为少做它而返工。
> **一旦远程配置要改现有接口的语义（比如 kill switch 要让内容接口回一个特殊错误码），
> 那条"先做后端"的理由就又生效了 —— 那时先做 6b-3。**
>
> 部署（6b-2）依然建议早做，而且你已明确排在"本地完全跑通"之后，没问题；
> 但要记住：**它是唯一能暴露"机房 IP 被针对 / 源站改版"这类问题的一步**，
> 而那类问题一旦出现，改的往往是方案而不是代码。

**为什么现在可以把"冷通道回填资产库"划掉了：** 实现时用
**缓存 + 主动预热**代替了它 —— 少一层存储，少一整类"数据什么时候过期"的问题。

## 六、悬而未决 / 需要你决定的

| 事项 | 说明 | 影响 |
| --- | --- | --- |
| **有没有 Mac** | 打包 ipa 需要 Mac + Xcode | 决定最后一步会不会卡住。可以租云 Mac |
| **Apple 开发者账号（$99/年）** | 免费证书**7 天就过期**，App 会直接打不开 | 基本是**必需**的，否则"只打包一次"这个前提在 7 天后就废了 |
| 第一版做不做 `search` | 两个源都没通（`ncat21` 要 token，`ai2048` 接口未找到） | 影响前端要不要留搜索框 |
| `rating` 字段留不留 | `2048ai` 有真实评分 9.4 | 影响契约（现在没有这个字段） |
| 要不要做分片级去广告 | 去掉 m3u8 里的广告 `.ts` | 工作量不小，得先有明确的广告样本 |
| 公告 / 源开关 / kill switch 的**具体字段** | 阶段 6 的第一件事 | 直接决定后台界面长什么样 |
| **后端图片代理还做不做** | 挖出来的 403 说明它救不了 `ncat21`（见顶部卡点）| 要做的话，理由得改成"缓存 + 私有化出口 + 未来源兜底" |
| **播放代理（阶段 9）要不要提前** | `ai2048` 的 m3u8 有来源白名单，浏览器直连必坏 | 若 iOS 原生播放真的能绕过，优先级可以降；先拿真机验一下 |

## 七、已知的债与可选优化（不阻塞）

| 项 | 说明 |
| --- | --- |
| 播放超时**按源可配** | 现在全局 20s/25s。`ncat21` 慢是它自带 1 秒限速造成的，源自己最清楚自己的节奏 —— 超时应该写进源的 `meta` |
| `rou.video` 还没接 | 它带加密，需要单独处理；也是设计"爬虫生成器"时最重要的第 3 个样本 |
| 预热"热门详情" | 现在只热首页 + 前 3 个分类。要热哪几部需要一个"什么算热门"的定义（否则就是定时去爬整个站） |
| 预热的抖动/错峰 | 单实例没有惊群问题，多实例时必须加 |
| 缓存命中率没有指标 | 现在只能在 `/admin/status` 上看到累计 hits/misses，没有趋势、没有按源拆分 |
| 熔断状态不持久化 | **刻意如此**：重启本身就是一次"重新试探"。但重启后没有任何历史，排查时看不到"它昨天熔断过三次" |
| 没有全局请求限流 | 现在只限制了"同时跑几个爬虫"。如果哪天有人拿激活码疯狂刷，需要一个按设备的限流 |
| `docs/architecture.md` 的第 4/6 节仍偏设计稿口吻 | 已标状态并改掉与实践冲突的部分，但前端那节的组件名还是预想的 |
